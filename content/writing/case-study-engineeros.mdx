Every engineer I know runs the same broken setup: notes in one app, tasks in
another, docs in a third, and the actual knowledge — the *why* behind decisions
— scattered across all of them. Context dies in the gaps. EngineerOS is my
attempt to fix that.

## The assumption that was wrong

I started clean: **the problem is storage.** Put notes, tasks and docs in one
database with one schema and the fragmentation disappears. Build the unified
data model, ship a nice interface, done.

That survived about two weeks of real use.

## Where it broke

**Keyword search was useless.** The first search was plain SQL `ILIKE`. People
search by *meaning*: they type *how did I handle rate limits* and the note that
answers it is called *throttling middleware*. Keyword search returns nothing,
and from the user's side the workspace looks empty even though the answer is
right there. Fragmentation solved, discovery still broken.

**The assistant hallucinated confidently.** The moment an LLM sat on top of the
corpus it invented answers that sounded right and were wrong. For a workspace
people trust with real decisions, a confident wrong answer is worse than no
answer — it erodes trust in the entire product on the first bad response.

**Local-first felt great until search needed the server.** I wanted the snappy
feel of a local-first notes app. But semantic search needs server-side compute
and the vector index, so every interaction round-tripped and the "snappy" app
became molasses.

## The fixes shaped the system

- **Next.js with React Server Components** — reads render where the data and
  the vector index already live, so search never pays a client round trip.
  Editing stays local.
- **Supabase: PostgreSQL + pgvector** — one store for auth, the relational
  workspace *and* the embeddings. Keeping vectors beside the rows they describe
  means retrieval can filter by relationship in the same query that does the
  similarity search.
- **A citation-backed assistant** — it answers *only* from retrieved chunks and
  attaches the source note to every claim. No source, no claim. That one
  constraint turned it from something that lies into something people trust.
- **A real knowledge graph** — notes, tasks and projects are nodes with edges,
  so the assistant can traverse *this task came from that decision* instead of
  treating each record as an island.
- **User-owned storage** — your data lives in your Supabase, not my black box.

## The tradeoffs worth naming

Local-first UX vs. server-side intelligence was not resolved by picking one. It
was resolved by drawing the line: edits local, intelligence remote.

Cost predictability with multi-step agents came from checkpointing plus bounded
steps, because an unbounded agent loop can silently multiply a token bill.

And trust beat helpfulness. An assistant that says *I don't have a note on that*
is less impressive in a demo and more useful in practice.

## The result

Live. Semantic search at under 200ms p95 over an HNSW index, with every claim
carrying its source.

The number I care about is not the latency. It is that **10+ people now use it
daily and lean on it hard.** A workspace only proves itself when people trust it
with the thinking they cannot afford to lose.

**Unifying storage is easy. Unifying *context* is the actual product.**
