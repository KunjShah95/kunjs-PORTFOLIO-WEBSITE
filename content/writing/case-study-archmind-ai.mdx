Architecture review has always been a slow, senior-engineer-only bottleneck.
Diagrams sit in wikis and rot. Risks go unnoticed until an incident. Teams
have no tooling that evaluates a design across the tradeoffs it actually trades
off. I built ArchMind AI to change that.

## The three structural problems

1. **Review is bottlenecked on seniority.** Never enough staff engineers, and
   most reviews happen as a rubber stamp after the decisions are made.
2. **Architecture knowledge is static.** The diagram is a photograph of a
   decision, not a live model. There is no way to ask *what breaks if this
   service fails?*
3. **Tradeoffs are invisible.** A design can be scalable but insecure, cheap but
   fragile, and nothing scores across all the axes at once.

## Seven specialists, one graph

Everything is parsed into a single unified graph — nodes for services, stores
and clients, edges for calls — and seven agents score independent dimensions
against it: Scalability, Security, Reliability, Performance, Cost,
Maintainability, Observability.

This was the central architectural call. A single monolithic analysis prompt
blends security reasoning into cost reasoning into reliability reasoning and
produces mush. Each dimension has genuinely different evaluation logic, so each
gets its own rubric and its own severity scale.

Architecture review is inherently multi-agent for exactly the reason it is
inherently senior-only: a security engineer, an SRE and a cost analyst do not
review a design the same way.

Parsing everything into one graph also means the agents, the chaos simulator
and the compliance auditor are each written once rather than four times.

## Zero-config is a product decision

The hard engineering problem was the LLM strategy. Requiring an API key before
the product does anything useful creates a chicken-and-egg problem — you cannot
evaluate a tool you have not configured.

The answer was a fallback chain: Groq, NVIDIA, OpenRouter, Gemini, Ollama,
HuggingFace. And when none are configured, an eighteen-rule heuristic engine
that produces a real baseline score. No keys and the product still works; add
one provider and it upgrades itself.

That heuristic baseline changed the product more than any feature did.

## Cold starts are a UX problem

Render's free tier spins down after fifteen minutes, so the first request after
idle hit a forty-second cold start. The first instinct was to blame the
frontend — the interface looked broken. Client-side warming fixed the symptom; a
scheduled keep-warm workflow fixed the cause. A hotter instance would also have
fixed it, for money.

## The result

Live, with source open. Upload a diagram or paste code, get a multi-dimensional
score with prioritised, attributed findings.

**Architecture review should be automated, continuous and multi-dimensional —
not a rubber stamp from the one senior engineer who has time.**
