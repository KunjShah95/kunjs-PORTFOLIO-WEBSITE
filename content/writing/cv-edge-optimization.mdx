Running YOLOv8 on a workstation with an A100 is a breeze. Running it on a
fanless industrial PC at the edge of a railway track, detecting wagon defects in
real time, is where the engineering actually is.

For Railway Inspection the target was sub-100ms end to end: frame ingestion,
preprocessing, inference and post-processing combined. Here is how that works.

## 1. Moving beyond Python

Python is excellent for research and a genuine bottleneck for high-speed
per-frame inference on an edge device. I moved the entire pipeline to C++ and
compiled the YOLOv8 ONNX export to a TensorRT engine tuned specifically for the
Jetson Orin's architecture. That alone was roughly a 3x speedup.

The engine file is architecture-bound. It is a deployment artefact, not a build
output — you ship a different binary per device.

## 2. The preprocessing pipeline

Often the bottleneck is not the model, it is the data preparation. I built a
multi-threaded GStreamer pipeline for hardware-accelerated decoding and moved
resize and normalisation onto the GPU as CUDA kernels, which kept the CPU free
for logic and networking.

On an edge device this is not a micro-optimisation. Every host round trip in
the hot path costs more than the inference itself.

## 3. Smart quantisation

FP16 is safe. INT8 is where the real gains are, and naive INT8 quantisation will
quietly destroy small-defect accuracy — exactly the low-magnitude signal a
detector lives on.

Quantisation-aware training during the final epochs lets the weights adapt to
the precision budget they will run under. That held detection accuracy above
98% while cutting inference time in half.

The mechanism matters: the defects that get quantised away are the ones with
low activation magnitude, and during QAT the network learns to represent them in
the bits it will have. You cannot recover that after the fact.

## 4. Handling environmental chaos

Industrial environments are not clean labs:

- **Motion blur** — trains move fast. Optimised shutter speeds plus a
  lightweight deblurring kernel on capture.
- **Low light** — inspections happen at all hours. Real-time histogram
  equalisation before the frame reaches the network.

Both of these look exactly like model failure. Neither is. When edge accuracy
drops in real conditions, suspect the environment before the weights — mine
did, twice.

## The summary

The edge is not about the model. It is the marriage of hardware-specific
optimisation and robust software engineering. When you are counting
milliseconds, every byte of memory and every instruction cycle is being
counted by something.
