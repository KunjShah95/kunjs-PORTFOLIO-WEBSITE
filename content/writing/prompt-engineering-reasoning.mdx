Getting a model to do one thing is easy. Getting it to reason through a
multi-step problem while holding accuracy and consistency is a different
discipline.

## Chain-of-thought

Chain-of-thought changed the picture. Instead of asking for an answer, you ask
for the reasoning:

**Before:** "What is 234 × 89?"

**After:** "Let's work through this step by step. First, multiply 234 by 9…"

For anything beyond a single step, this is the baseline rather than the trick.

## Three patterns worth knowing

**ReAct — reason then act.** The model thinks about what to do, acts, observes
the result, and adjusts. This is the pattern underneath essentially every
agentic system, and it is why agent loops are where prompt fragility shows up
first.

**Tree of thoughts.** For problems with several valid approaches, generate
multiple reasoning paths in parallel and evaluate which leads somewhere. Useful
for planning and for anything where the first plausible path is often a
cul-de-sac.

**Self-correction loops.** Make correction an explicit stage: generate a
solution, review it for errors, correct and repeat if needed, proceed if not.
Crucially, the review must be a separate step. Asking a model to check its own
answer in the same breath is asking it to do two things at once, and it does
the second one badly.

## Structured output

For anything production-shaped, the output format cannot be a request:

1. **Delimited sections** — separate analysis from answer with explicit tags
2. **Schema in the prompt** — the exact structure, spelled out
3. **A parser that validates** — parse into a typed object, and reject rather
   than coerce when it fails

That third one is the one people skip, and it is the one that matters. A
malformed response that gets coerced is a silent correctness bug, and at volume
it is invisible.

## How you know whether it is working

1. **Consistency** — run the same query five times, measure variance
2. **Adversarial** — edge cases and injection attempts, not just the happy path
3. **Step verification** — verify each step independently rather than trusting
   the final answer
4. **Human eval** — have people who know the domain rate outputs

## The mistake almost everyone makes

Writing the prompt once. I treat prompts like code: version-controlled, tested
against a diverse example set, measured over time, and refactored when they
grow past what a person can hold in their head.

The best prompting is invisible. The user gets the right answer without knowing
any of this was done.
