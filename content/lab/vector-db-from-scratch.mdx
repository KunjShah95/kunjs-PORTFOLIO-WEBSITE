## What I was testing

Whether "we need a vector database" is a decision or a habit. Every AI
application reaches for one, and the choice of index inside it is made by
default rather than by measurement. I wanted to know what the trade-offs
actually were.

## Method

Built a vector database with no dependencies: nine approximate nearest
neighbour algorithms, a cost-based query planner across them, a crash-durable
write-ahead log, multimodal ingestion, GPU-accelerated index construction, and
SDKs in six languages.

The index implementations, with recall and the cost profile of each:

| Algorithm | Recall | Index build | Query | Memory |
|---|---|---|---|---|
| HNSW | 99.2% | Slow | Fastest | High |
| IVF + HNSW | 97.8% | Medium | Fast | Medium-high |
| SCANN | 96.3% | Slow | Fast | Medium |
| IVF | 94.1% | Fast | Fast | Medium |
| IVF + PQ | 91.5% | Fast | Fast | Low |
| NSW | 92.7% | Medium | Medium | Medium |
| Annoy | 90.8% | Fast | Fast | Medium |
| KD-Tree | 87.4% | Fast | Fast (low-D) | Low |
| Brute force | 100% | — | Slowest | n/a |

The planner estimates execution cost from dimensionality, dataset size, filter
selectivity, required recall and available memory, then picks an index. Against
an exhaustive sweep it selects the optimal index about 94% of the time.

## Result

HNSW is the answer to almost every production question: 99%+ recall at
sub-millisecond query on million-scale data, paid for in memory and in build
time. The planner saves users from having to know that.

Two results mattered more than the algorithms:

**Durability is most of the engineering.** The index logic is straightforward.
Surviving a power cut at an arbitrary point — fsync per write, append-only
segments with compaction, checksummed entries, replay from the last checkpoint —
is where the actual complexity is.

**GPU index construction changes the workflow.** HNSW build on 10M vectors
went from roughly eight hours on a 32-core CPU to about twelve minutes on one
A100. That is not a speedup, it is a different relationship with iteration.

## What it changed

How I pick an index. The default is no longer *whatever the library picked* —
it is a function of recall requirement, filter selectivity, and memory budget,
which I can now state explicitly.
