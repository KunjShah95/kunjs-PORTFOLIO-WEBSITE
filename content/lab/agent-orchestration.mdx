## What I was testing

I kept seeing the claim that agentic systems are hard to productionise, and the
usual explanation was model capability. That did not match what I was seeing:
the failures were boring and structural. So I started cataloguing them.

## Method

Collected failures from every multi-step agent workflow I have shipped —
ArchMind's seven-agent analysis, the research agent's four-stage pipeline,
EngineerOS task orchestration — and classified them by cause rather than by
symptom.

## Result

Three causes account for nearly all of it.

**No state persistence.** A ten-step reasoning chain that fails at step eight
restarts from zero, paying for eight steps twice. Checkpointing every step
turns a hard failure into a resume. This is not an optimisation, it is the
difference between recoverable and not.

**Unbounded step counts.** Multi-step LLM workflows can silently multiply a
token bill by an order of magnitude, and nothing in the framework stops it. An
explicit step ceiling makes the cost of a run predictable before you start it.

**No verification stage.** The agent produces a result and trusts it. Adding a
check that the result is supported by the evidence that produced it catches the
confident-wrong-answer class of failure, which is the one that damages trust
permanently.

The secondary pattern: flat agent topologies are brittle. A supervisor with
restricted-tool workers limits the blast radius of any single agent mistake, and
the restriction is what does the work — not the supervision.

## What it changed

Checkpointing and bounded steps are in every workflow I have shipped since. The
verification stage is why ArchMind has a zero-config heuristic baseline at all:
if the model path fails, the answer is a baseline score, not a wrong score.

## Still open

Whether verification can be cheap enough to run by default. A full second
generation doubles cost. A small model scoring claim-against-source is the
version that might make it unconditional.
