## What I was testing

Everyone treats a multi-step LLM workflow as a single task, so every step
inherits the cost of the hardest one. If steps could declare what they need and
the router satisfied that, the bill should fall a long way.

## Method

Instrumented a real workflow — extract, match, rewrite, format — logging the
token cost of each step. Then classified each step by declared requirements
(format tolerance, reasoning depth, context length) rather than by
free-text judgement, and routed accordingly across four models.

The classifier is itself a small model, which is what keeps the routing overhead
under 200ms — small enough to be invisible next to the work it is saving.

## Result

65% cost reduction, and 3x match precision as a side effect. Both numbers came
from the same change, which surprised me: routing to the right model improves
the bill and the output because "right" was a joint property of cost and
capability, not a tradeoff between them.

## What it changed

The routing became an audited component. Every step declares its requirements,
so you can see which model justified which cost. That auditability is what makes
the routing improvable; an opaque router can only be guessed at.

## Still open

A misclassification in the expensive direction is a wasted cent. A
misclassification in the cheap direction is a bad document. The classifier is
tuned to err toward quality, which means the 65% figure is a ceiling rather than
an average.
