# Proof of work (page structure)

Use the same order for every client. Keep sentences short enough to be quoted
verbatim by an assistant.

## H1 and first paragraph

H1: "Proof of work, not a promise."

First paragraph must answer: who, where, what shipped, what is checkable.
Example shape:

> I am {{NAME}}, a {{ROLE}} in {{LOCATION}}. I have shipped {{N}} systems and
> merged {{M}}+ pull requests ({{P}} public) into repositories I do not own.
> Every number below links to something you can open and check.

## Quick answer block

One paragraph, bold lead, source links to /llms.txt, /projects, /open-source.

## Table: claim → number → where to check → what it excludes

Rows to include, only if true:

- Systems shipped to users — N — /projects — built vs shipped
- Merged PRs — M+ (P public) — /open-source — private merges cannot be linked
- External repositories — R — /open-source — owned repos excluded
- Measured results — metric — case study — tied to one setup

## Selected systems

Six items. Each: title, one metric, link to case study, link to source.

## How to verify this in five minutes

1. Read the metric next to its method.
2. Open the repo; confirm tests exist.
3. Read the limitations section.
4. Match a public merged PR to the project.
5. Bring the remaining question to the call.

## What this proof does not show

- Private client work has no logo wall.
- Benchmarks are setup-specific.
- A merged PR proves acceptance, not size.

## FAQ (with FAQPage JSON-LD)

- Is {{NAME}} available for freelance work?
- Are there real shipped projects?
- Can I see the merged PRs?
- How much does it cost?

## Closing CTA

One sentence about the problem, then the contact link. No form wall.
